# 2. 홈페이지관리 사용·기술 설명서

공개 사이트 문구·사진·공지·문의를 **직원이 고치는** 영역입니다.  
대상: **관리자(`admin`)**, **슈퍼바이저(`supervisor`)**.  
경영(`ceo`)은 이 메뉴에 들어가지 않습니다.

---

## A. 유저 매뉴얼

### A-1. 들어가기

1. 헤더에서 로그인합니다. (`/account/login`)
2. 로그인 후 `/sitemap`에서 **홈페이지관리**를 고르거나 `/manage`로 이동합니다.
3. **관리자**는 한국시간 **09:00–18:00**에만 세션이 유지됩니다. 그 밖 시간에는 다시 로그인할 수 없습니다.  
   **슈퍼바이저**는 시간 제한이 없습니다.

### A-2. 관리 홈 `/manage`

대시보드 카드로 각 메뉴로 이동합니다.  
갤러리 등 업로드는 **재배포 후 파일이 비는지** 확인하라는 안내가 있습니다.

### A-3. 메뉴별 사용법

| 메뉴 | 경로 | 하는 일 |
|------|------|---------|
| 메인 영상·음악 | `/manage/home-hero` | 메인 배경 영상·BGM 등록·변경 |
| 메인 이벤트·팝업 | `/manage/announcements` | 접속 시 뜨는 이벤트·팝업 |
| 갤러리 | `/manage/gallery` | 둘러보기 사진 올리기·고치기·지우기 |
| 장례·안치 | `/manage/funeral` | 공개 장례·안치용 PDF 등 |
| 공지 | `/manage/notices` | 고객센터 공지 작성 |
| 문의 | `/manage/inquiries` | 접수 문의 열람, **내부 메모** 남기기(자동 메일 없음) |
| 묻고답하기 | `/manage/faq` | FAQ 항목 관리 |
| 인사말 등 본문 | `/manage/pages/{slug}` | CMS 본문 편집(아래 표) |
| 관리자 계정 | `/manage/admins` | **슈퍼바이저만** 직원 계정 관리 |

**CMS 본문 slug**

| slug | 공개 화면 |
|------|-----------|
| `greeting` | `/intro/greeting` |
| `features` | `/intro/features` |
| `burial` | `/lots/burial` |
| `lawn` | `/lots/lawn` |
| `columbarium` | `/lots/columbarium` |
| `remodeling` | `/lots/remodeling` |
| `prices` | `/lots/prices` |

### A-4. 권장 작업 순서

1. 메인 영상·팝업이 맞는지 확인  
2. 인사말·분양·가격 본문 수정 후 공개 URL에서 미리보기  
3. 갤러리·장례 PDF 업로드 후 `/gallery`, `/guide/funeral` 확인  
4. 공지·FAQ 게시  
5. 문의함 주기적으로 열어 내부 메모·후속 연락

### A-5. 하지 말 것

- 문의 답변을 “사이트에서 고객에게 자동 발송”된다고 안내하지 않습니다.
- 갤러리에 개인이 식별되는 묘비 클로즈업을 올릴 때는 내부 기준을 따릅니다.
- 관리자 계정 화면은 슈퍼바이저가 아닌데 URL을 직접 열어 쓰지 않습니다(리다이렉트됨).

### A-6. 문제 해결(사용자)

| 증상 | 조치 |
|------|------|
| `/manage`가 로그인으로 감 | 역할이 admin/supervisor인지 확인 |
| ceo로 로그인했는데 CMS가 안 보임 | 정상. 경영관리만 사용 |
| 근무 외 시간에 admin 끊김 | 정상(09–18 KST). 슈퍼바이저 계정으로 긴급 작업 |
| 갤러리 올린 뒤 공개에 없음 | 태그·게시 상태, 잠시 후 새로고침, 재배포 직후면 B-3 |
| `/manage/admins`가 `/manage`로 돌아감 | admin 계정임. 슈퍼바이저에게 요청 |

## B. 테크니컬 매뉴얼

### B-1. 접근 제어

```ts
// requireCmsStaff()
// - isCmsStaff: supervisor | admin
// - ceo → 경영 홈으로 redirect
// - 비로그인 → /?login=1

// requireCmsStaff(true)  // 관리자 계정 화면
// - role === "supervisor" 만 통과
// - admin → /manage 로 redirect
```

| 경로 | 가드 |
|------|------|
| `/manage/*` 일반 | `requireCmsStaff()` |
| `/manage/admins` | `requireCmsStaff(true)` |

NAV: `src/lib/manage-nav.ts`의 `manageNavItems()`  
사이트맵 노출: `isCmsStaff(role)`일 때 `manage.homepage`.

### B-2. 데이터·API

- 공지·FAQ·문의·CMS 페이지·갤러리 메타: Mongo(또는 로컬 JSON 폴백, 환경에 따름)
- 업로드: `public/uploads/...` 및 GridFS 버킷(`site_uploads`) → `/api/uploads/...`
- 관리 API는 직원 세션·역할 검사가 있어야 합니다(각 `src/app/api/manage/...`).

### B-3. 갤러리·업로드·재배포

관리 화면 안내 요지:
> 올린 파일은 `public/uploads`에 저장될 수 있고, Render 디스크는 재배포 때 비워질 수 있습니다.

**운영 권장**
1. 가능하면 Mongo GridFS(또는 외부 스토리지) 경로를 확인한다.
2. 배포 직후 `/gallery`, 메인 히어로, 장례 PDF를 연다.
3. 비어 있으면 재업로드 또는 DB/스토리지 복구.

### B-4. 문의 처리 모델

- 고객 제출 → DB 저장
- 직원 화면의 답변/메모 = **내부용**
- 메일 서버 연동 발송 없음(현재)

### B-5. CMS와 고정 페이지

- CMS: greeting, features, burial, lawn, columbarium, remodeling, prices
- 코드 고정에 가까운 공개 화면: 분양 절차, 일부 이용안내 레이아웃
- CMS가 비면 코드 폴백 문구가 나올 수 있음 → “비어 보이면 폴백인지 확인”

### B-6. 점검 체크리스트

- [ ] admin·supervisor로 `/manage` 진입
- [ ] ceo는 CMS 미진입
- [ ] admin으로 `/manage/admins` 차단
- [ ] supervisor로 계정 목록 열림
- [ ] 본문 수정 → 공개 URL 반영
- [ ] 갤러리·히어로·장례 파일 공개 확인
- [ ] 문의 내부 메모 저장
