# 5. 슈퍼바이저 사용·기술 설명서

**슈퍼바이저(`supervisor`) 전용** 운영 화면입니다.  
다른 역할로 URL을 열면 로그인 또는 업무 화면으로 보내집니다.

이 권은 두 덩어리로 나눕니다.

- **제1부** 방문통계·DB·계정 등 **운영**
- **제2부** 계약·관리비·영수증·업무보고·기초정보 **원장**

업무프로그램(`/work/contracts` 등)과 메뉴 이름이 같아도 **경로와 기능이 다릅니다.**

---

# 제1부. 운영(방문통계·DB·계정)

## A1. 유저 매뉴얼 — 운영

### A1-1. 메뉴

| 메뉴 | 경로 | 하는 일 |
|------|------|---------|
| 방문 통계 | `/supervisor/stats` | 공개 UV/PV, 기간·추이, 직원 페이지뷰 요약 |
| DB 업데이트 | `/work/sync` | 원본 → Mongo 복사본 수동 갱신 |
| 관리자 계정 | `/manage/admins` | 직원 계정 발급·수정(슈퍼바이저만) |

사이트맵 **슈퍼바이저** 그룹에도 위 항목이 포함됩니다.

### A1-2. 방문 통계

1. `/supervisor/stats`를 엽니다.
2. 오늘·7일·30일·누적 공개 방문자(UV)·페이지뷰(PV)를 봅니다.
3. 최근 30일 추이 막대·직원 PV·조회 경로 요약을 확인합니다.
4. **MongoDB가 없으면** 통계를 쌓거나 보여줄 수 없다는 안내가 납니다. `MONGODB_URI`를 확인합니다.

통계는 공개 방문과 직원 이용을 구분합니다. 민감 경로·개인 식별 정보를 설명서에 붙여 넣지 마세요.

### A1-3. DB 업데이트

1. `/work/sync`를 엽니다.
2. **DB 업데이트**로 원본 Cemetery에서 자료를 다시 받습니다(전체 갱신에 가깝게 동작).
3. 진행률·결과를 보고, 계약·관리비·영수증·보고·묘지·기초정보 건수를 확인합니다.
4. 평소에는 **한국시간 새벽 1시** 차분 동기화(타이머)가 돌아갈 수 있습니다.  
   - 바뀐 목록만 반영, 원본에 없는 행을 함부로 지우지 않는 정책이 있습니다.  
   - 이 사이트가 원본을 완전히 대체하면 타이머를 끄는 설정(`WORK_SYNC_TIMER=0` 등)을 검토합니다.

자격·원본 URL·회사코드는 서버 환경변수에만 두고, 설명서에 비밀번호를 적지 않습니다.

### A1-4. 관리자 계정

1. `/manage/admins`에서 직원 ID·이름·역할·비밀번호를 관리합니다.
2. 역할: `admin` / `ceo` / (필요 시 정책에 따른 supervisor)
3. **admin**은 CMS·업무는 쓰지만, 이 계정 화면과 슈퍼바이저·DB동기화는 못 씁니다.
4. admin은 **09–18 KST**만 로그인 유지됩니다.

## B1. 테크니컬 매뉴얼 — 운영

### B1-1. 가드

- `/supervisor/*` → `requireSupervisor`
- `/work/sync` → 슈퍼바이저
- `/manage/admins` → `requireCmsStaff(true)`

### B1-2. 통계·동기화 의존성

| 기능 | 필요 환경 |
|------|-----------|
| 방문 통계 | `MONGODB_URI`, 통계 컬렉션 |
| DB 업데이트 | `MONGODB_URI`, `CEMETERY_SOURCE_*` |
| 새벽 차분 | instrumentation + `work-sync-timer`, `syncWorkDiffFromSource` |

### B1-3. 동기화 정책 요약

- 수동 버튼: 전면 pull·저장에 가깝음
- 야간: 목록 비교 후 변경분만, 계약서 파일은 목록 본문 변경·누락 시에만 재수집
- 수수료·영수증·보고·묘지: 컬렉션 digest가 다를 때만 교체
- 원본에 없는 행 삭제 금지(현장 **신규** 보존)

# 제2부. 계약관리·원장(관리비·영수증·보고·기초정보)

## A2. 유저 매뉴얼 — 원장

### A2-1. 메뉴

| 메뉴 | 경로 | 하는 일 |
|------|------|---------|
| 계약관리 | `/supervisor/contracts` | 묘번·사용자·연고자·전화·종류로 검색, 계약부 열람 |
| 관리비내역 | `/supervisor/fees` | 청구일자 구간·납부구분 조회, 행 클릭 시 내역 모달 |
| 영수증관리 | `/supervisor/receipts` | 기간·묘번·종류 조회, 행 클릭 시 영수증 모달 |
| 업무보고/현황 | `/supervisor/reports` | 보고 목록, 작성일자 클릭 시 업무일지 모달 |
| 기초정보 | `/supervisor/base` | 탭별 마스터 목록·검색·우측(또는 선택) 상세 |

### A2-2. 계약관리

1. 검색칸: 묘지번호, 사용자, 연고자, 전화, 종류(계약/이장/전체).
2. 조회하면 복사본 Mongo만 보고, 입력이 있으면 원본을 다시 치지 않습니다.
3. 행을 열어 계약부(저장된 inputs)를 읽습니다.
4. 페이지는 약 30건 단위입니다.

### A2-3. 관리비내역

1. 청구일자 시작~끝(기본 올해), 납부구분(전체·미납·납부중·보류·완납).
2. 목록: 청구일자·묘지번호·사용자 등.
3. 청구일자·묘지번호·사용자 등을 누르면 **관리비 내역 모달**(해당 계약/묘 기준 회차).
4. 하단 납부일자·납부자 표는 복사본에 없으면 안내 문구만 둡니다(없는 값을 만들지 않음).
5. 금액 0은 빈칸이 아니라 0으로 표시합니다.

### A2-4. 영수증관리

1. 기간(비우면 전체), 묘번, 종류(전체·관리비·계약비·시설비·공사비).
2. 목록: 거래년월일, 묘지번호, 고인성명, 일련번호, 거래금액.
3. 앞 항목을 누르면 **영수증내역** 읽기 모달(저장된 inputs).
4. 저장·출력·삭제는 현재 조회 중심으로 두고, 원본 버튼과 1:1이 아닐 수 있습니다.

### A2-5. 업무보고/현황

1. 목록: 작성일자, 처리건수, 청구자재, 입고자재, 특기사항, 출근현황.
2. 작성일자를 누르면 **업무일지**: 업무사항(묘지번호·진행·결과), 예정사항, 자재·특기·출근.
3. 원본 건수가 적으면(예: 1건) 복사본도 그에 맞습니다.

### A2-6. 기초정보

탭:

| 탭 | 검색 라벨 | 목록 요지 |
|----|-----------|-----------|
| 묘지정보 | 묘지번호 | 묘지번호·평수·위치·사용여부 |
| 관리비기준 | 고지번호 | 고지번호·일자·금액·비고 |
| 석물코드 | 석물명 | 코드·명·규격·단위·단가·사용 |
| 회사정보 | (검색 없음) | 코드·상호·대표·주소 + 상세에 사업자·전화·계좌 등 |
| 사용자 | 사용자명 | ID·명·등록일·사용 (**비밀번호 칸 없음**) |
| 상담코드 | 상담코드명 | 코드·명·사용 |

1. 탭을 고르고(회사는 검색칸 숨김) 필요 시 검색합니다.
2. 행을 고르면 오른쪽 상세 칸이 채워집니다(원본형 입력 레이아웃).
3. **묘지정보 순서는 원본 목록 순서**입니다. 가나다 재정렬하지 않습니다. 첫 페이지는 원본과 같이 `가122-2` 등부터 시작합니다.
4. 위도·경도는 칸만 두고, 원본에 값이 없으면 비어 있습니다.
5. 저장·수정·삭제·출력 버튼은 원본 자료를 바꾸는 기능이라, 현재는 **조회**에 맞춥니다.

### A2-7. 업무프로그램과 헷갈릴 때

| 하고 싶은 일 | 갈 곳 |
|--------------|--------|
| 전 직원이 계약 목록만 | `/work/contracts` |
| 묘번·전화로 깊게 찾고 계약부 | `/supervisor/contracts` |
| 청구일·납부구분 + 모달 | `/supervisor/fees` |
| 업무일지·기초 탭 | `/supervisor/reports`, `/supervisor/base` |
| 경영 집계 표 | `/work/exec/...` |

## B2. 테크니컬 매뉴얼 — 원장

### B2-1. 컬렉션(요지)

| 화면 | 저장 |
|------|------|
| 계약 | `contracts`, `contract_files` |
| 관리비 | `fees` |
| 영수증 | `receipts`(+ year, receiptNo, inputs) |
| 보고 | `work_reports`(+ tasks, plans, attendance…) |
| 묘지 | `cemetery_info` (`sort({ _id: 1 })`로 원본 삽입순) |
| 기초 마스터 | `base_items`(kind: cost/stone/company/user/consult, fields) |

### B2-2. 파서·소스

- `cemetery-parse.ts` / `cemetery-source.ts` / `work-store.ts` / `work-sync.ts`
- 기초 상세: `parseDetailFields`, `fillBaseDetails`
- 사용자 비밀번호 컬럼은 파싱에서 제외

### B2-3. UI 컴포넌트

- 계약: `supervisor-contract-book`
- 관리비: `supervisor-fee-list`
- 영수증: `supervisor-receipt-list`
- 보고: `supervisor-report-list`
- 기초: `supervisor-base-book` + `lib/base-book.ts`  
  (서버가 클라이언트 전용 export를 직접 호출하지 않도록 탭 상수는 `base-book`에 둠 — React #441 방지)

### B2-4. 현재 범위(문서에 명시)

- 조회·검색·모달/상세 읽기 중심
- 원본의 저장·삭제·출력·납부자 회차 입력은 미구현 또는 부분
- 영수증·보고·기초 건수는 원본 기본 검색과 맞춰 둔 상태(동기화 시점 기준)

### B2-5. 점검 체크리스트

**운영**
- [ ] stats에 Mongo 있을 때 숫자 표시
- [ ] sync 수동 실행·결과 건수
- [ ] admins는 supervisor만

**원장**
- [ ] 계약 검색 응답이 원본 재호출 없이 빠른지
- [ ] 관리비·영수증 모달
- [ ] 보고 일지 업무/예정
- [ ] 기초 6탭, 묘지 첫 행이 원본 순
- [ ] 사용자 상세에 비밀번호 없음
